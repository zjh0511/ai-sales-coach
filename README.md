# AI業務教練｜豪老師 Hao+

以語音角色扮演為核心的 AI 業務訓練工具，協助保險業務人員反覆練習邀約、需求探索、
商品說明與異議處理，並在每次演練後得到五項能力評分與教練回饋。

**👉 直接使用：https://zjh0511.github.io/ai-sales-coach/**

> ⚠️ 本工具僅供自學訓練參考，請勿公開分享生成內容。
> 業務員網路言行不得涉及招攬保險或招募行為。
> 本工具不提供法律、稅務、醫療或財務建議。

## 六大功能

| # | 功能 | 說明 |
|---|---|---|
| 1 | 客戶潛在痛點分析 | 輸入客戶背景 → 三個潛在痛點（含推測原因、需求方向、可直接問出口的探索問題）＋ 建議接觸方式 |
| 2 | 電話邀約語音對練 | AI 扮演客戶進行語音通話演練 → 五項評分 ＋ 教練回饋 |
| 3 | 發掘需求角色扮演 | 客戶有隱藏需求，只有問對問題才會鬆口；畫面即時顯示挖到幾項 |
| 4 | 商品行銷語音演練 | 上傳公司教材 → 自動整理 FABE 賣點與常見疑慮 → 演練前先看「商品重點」（可再產生教練講解）→ 針對該商品演練，回饋逐點檢查必講重點 |
| 5 | 客戶理賠諮詢建議 | 客戶的狀況 → 勾選客戶的保單（可多張、填保額）→ 各保單可能給付項目、程式試算金額、依據條文，以及可以直接回覆客戶的話術 |
| 6 | 問問其他問題 | 與教練討論客戶狀況、話術或法規疑問（可打字，也可語音對談，教練聲音可選男／女），違規建議會被當場糾正 |

## 沒有伺服器

這是一個**純前端**應用程式。所有運算都在你自己的瀏覽器裡完成，
瀏覽器直接呼叫你所選的 AI 服務商，中間不經過任何第三方伺服器。

因此：

- **沒有冷啟動**，打開就能用
- **金鑰只存在你的裝置**，不會傳給任何人
- **上傳的文件存在你自己的瀏覽器**（IndexedDB），永久保留，不會因為服務重啟而消失
- **訓練紀錄預設也存在本機**

### 帳號同步（已啟用）

打開網站會先看到註冊／登入畫面，可以用 **Google 帳號**或 **E-mail** 登入，
**訓練紀錄與偏好設定**會跟著人跑，換手機、換電腦都接得起來。

- **API 金鑰、上傳的教材與保單條款永遠不上雲端**，這是程式碼層面的限制，不是設定選項
- 開啟同步後，訓練紀錄會經過 Google 的伺服器；資料庫擁有者在後台看得到，**這一點應事先告知使用者**
- **登入是必經關卡**，每位使用者都要有帳號。若 Firebase 出問題需要緊急放行，清空 `apiKey` 再 push 即可關閉登入關卡
- Apple 登入需要付費的 Apple Developer 帳號（Apple 的規定），程式碼已備好但預設關閉
- 設定值放在 [docs/firebase-config.js](docs/firebase-config.js)，清空 `apiKey` 就能整段關閉帳號功能
- 安全規則見 [database.rules.json](database.rules.json)，改動後請跑 `node tools/fbcheck.mjs` 驗證

## 開始使用

### 1. 申請一把免費的 AI 金鑰

1. 前往 https://aistudio.google.com/apikey
2. 用 Google 帳號登入 → **Create API key**
3. 複製那一長串金鑰

### 2. 打開網站並登入

https://zjh0511.github.io/ai-sales-coach/

服務商選「Google Gemini」，把金鑰貼上去，按「驗證並登入」。

### 3. 加入主畫面（建議）

這是一個 **PWA**，可以裝到桌面當成獨立 App 使用：

**打開網址的第一個畫面（還沒登入）就有一顆「📲 先加到主畫面」按鈕**，登入頁與首頁也各有一顆。按下去會依你的裝置給出正確的下一步：

- **Android／桌面 Chrome**：直接跳出系統的安裝視窗，一鍵完成
- **iPhone／iPad**：跳出圖示教學，依你用的瀏覽器指出分享鍵在哪
  （Safari 在最下方／iPad 右上角，Chrome 在網址列右邊，Edge 在 ⋯ 選單裡）。
  **iOS 不允許網頁自己建立捷徑**，這是 Apple 的限制，任何網站都一樣；
  但 **Safari 與 Chrome 都做得到**，做出來的捷徑都是全螢幕開啟
- **從 LINE／Facebook 點連結進來**：那些內建瀏覽器根本沒有「加入主畫面」，
  按鈕會先教你怎麼換到系統瀏覽器（Safari 或 Chrome 都可以）
- 已經安裝過的話按鈕會自動消失

**建議的順序是「先加到桌面，再從桌面 App 裡登入」。**
iOS 上桌面 App 的儲存空間與 Safari 是分開的——先在瀏覽器登入根本帶不過去，
從桌面圖示開啟後還是要再登入一次。所以按鈕刻意放在登入之前。

裝好之後從桌面圖示開啟是全螢幕、沒有網址列，長按圖示還有捷徑可以直接跳到
電話邀約／發掘需求／痛點分析。

**離線時介面打得開，但演練需要網路**——AI 回應必須連到服務商的 API。

## AI 服務商：只用 Google AI Studio

**目前只開放 Google AI Studio 的 API 金鑰**（免費、不需要信用卡，申請教學在登入頁）。

| 項目 | 說明 |
|---|---|
| 預設模型 | **Gemini 3.5 Flash Lite**——角色扮演與評分都用它 |
| 塞車時的備援 | 3.1 Flash Lite → 3.7 Flash → 3.6 Flash → 3.8 Flash，自動切換 |
| 可直接讀 PDF | ✅ |

之前用 Groq、OpenRouter 等其他服務商登入過的人，下次開啟會被請回登入頁，
畫面會說明原因，貼上 Gemini 金鑰即可。

> 引擎本身仍支援 OpenRouter、Groq、Anthropic、OpenAI、DeepSeek（`docs/engine/gateway.js`），
> 只是沒有開放選擇。要恢復的話，把服務商代號加回 `docs/engine/api.js` 的 `ENABLED`。

登入時會實際向 Google 驗證金鑰，有問題當場就會告訴你。

**Google 那邊全面塞車時**（2026-09-29 實際遇過：連只回一個字的請求，每個模型都回 503），
畫面會明講「服務商塞車，不是你的金鑰或操作的問題」，而不是模糊的「卡了一下」。
演練中遇到的話，逐字稿不會消失，等一下再按「重新評分」即可。

### 模型設定

登入後，首頁下方的「模型設定」會顯示目前使用的模型，點進去可以更換。
清單是用你這把金鑰**即時查詢**出來的，不同帳號看到的不一樣。

- 預設是**自動**，也就是 Gemini 3.5 Flash Lite，不確定選哪個就別動它。
- 推薦的模型排在最前面並標 ★。

**自動模式的內部行為**：引擎仍保留「角色扮演」與「評分」兩條獨立的挑選順序
（規格 §47 Judge Model 分離），但目前兩條的第一順位都是 3.5 Flash Lite（使用者指定）。
一旦你指定了某個模型，全部功能都會改用它。

**指定模型不會關掉自動降階。** 遇到下列情況會自動改用下一個模型，並在畫面上提示：

| 狀況 | 處理 |
|---|---|
| 額度用盡（429） | 換下一個，十分鐘後回頭試原本的 |
| 需求量過高（503） | 只重試一次就換，一分鐘內不再撞同一個 |
| 模型對這把金鑰已下架（404） | 直接略過，這次使用期間不再試 |

練習不會中斷，也不會默默變差而你不知道。

> ⚠️ 只在你信任的網址輸入金鑰。任何人要求你把金鑰貼給他，都應該拒絕。
> 共用裝置請記得使用完登出（首頁下方「登出／更換金鑰」）。

## 在自己電腦上開發

### 需要

- [Node.js](https://nodejs.org) 20 以上
- Git for Windows（產生憑證用，內含 openssl）

```bash
git clone https://github.com/zjh0511/ai-sales-coach.git
cd ai-sales-coach
node tools/gencert.mjs      # 產生本機 HTTPS 憑證（手機用麥克風必須走 HTTPS）
node tools/serve.mjs        # 啟動本機靜態伺服器
```

| 用途 | 網址 |
|---|---|
| 電腦除錯（免憑證） | `http://localhost:8444` |
| 手機（需同一個 Wi-Fi） | `https://<你的區網IP>:8443` |

`tools/serve.mjs` 只是個靜態檔案伺服器，正式站不需要它。

### 自我測試

```bash
node tools/selftest.mjs        # 跑完六大功能共 60 項檢查
node tools/selftest.mjs 5      # 只跑第 5 節
node tools/fbcheck.mjs         # 帳號同步與安全規則（改過規則就要跑）
```

需要一把 Gemini 金鑰，放在專案根目錄的 `Gemini API Key.txt`，
或設定環境變數 `GEMINI_API_KEY`。這兩者都在 `.gitignore` 內。

### 文件解析策略

| 格式 | 做法 |
|---|---|
| `.docx` / `.pptx` | 瀏覽器內解 ZIP 讀 XML（`DecompressionStream`） |
| `.pdf` | 直接把原始檔交給模型讀，中文與掃描版都比自寫解析器可靠 |
| `.txt` / `.md` | 直接讀 |
| `.doc` / `.ppt` | 不支援，請另存成新格式或 PDF |

上傳時做一次「知識結構化」（規格 §41），之後查詢用摘要即可。
理賠查詢因為準確度要求高，會回頭比對條款原文。

**投影片如果大多是圖片，取到的字會很少**——系統會直接警告你，並建議改用 PDF。

### 接觸情境與話術資訊邊界

演練前要先選「接觸情境」，這決定業務員**此刻合理知道客戶什麼**，示範話術只能在這個邊界內設計。
`demoLeaksPrivateInfo()` 會掃描產生出來的話術，若在陌生／轉介紹情境中出現保額、保單、
繳費金額等字樣，自動重新產生。

### 建立信任感（NLP）

示範話術與教練回饋遵循七原則：先跟後帶、語言同步、尊重自主權（給對方退路）、
開場交代「我是誰／為什麼是現在／為什麼是你」、先處理情緒再處理事情、
第一次接觸只求一個小承諾、問句從生活出發而非從錢出發。
依規格 §53，明文禁止用於操控、製造恐懼或假裝熟識。

### 話術中立化

系統產生的示範話術一律不預設保險公司：公司寫「○○人壽」、人名寫「○○」。
不套用於逐字稿、評分證據，以及上傳的條款與教材。

### 為什麼沒有 NVIDIA 和「用 ChatGPT 登入」

因為純前端架構下**技術上做不到**，不是沒做。2026-08-17 實機驗證：

| 目標 | 阻礙 |
|---|---|
| NVIDIA NIM | 整個 API 完全不回傳 `access-control-*` 標頭，瀏覽器直連被擋（`Failed to fetch`） |
| 用 ChatGPT 帳號登入 | 登入端點 `auth.openai.com` 允許瀏覽器呼叫，但拿到 token 後真正要用的推論端點 `chatgpt.com/backend-api/codex/*` 擋 CORS |

兩者都必須自架伺服器代轉每一次呼叫，那會失去 GitHub Pages 的所有好處（無冷啟動、永久免費、零維護），
而 ChatGPT 那條路還額外有條款疑慮——Anthropic 與 Google 已於 2026 年 2 月封鎖同類做法。

若日後真的需要，`docs/engine/api.js` 保留了與伺服器版相同的介面，加回代理層只需替換該層。

## 已知限制

1. **本機模型尚未接上。** 目前透過雲端 API。手機瀏覽器分頁記憶體約 1～1.5GB，
   跑不動 2～3GB 的裝置端模型；真正的裝置端推論須等原生 App 階段。Gateway 介面已預留。
2. **Barge-in 是「點擊打斷」而非自動偵測。** iOS Safari 無法在 TTS 播放時穩定同時收音。
   iPhone／iPad 上客戶講完後會等約 3.5 秒才開麥克風（iOS 音訊通道釋放很慢），
   畫面會顯示「正在切回麥克風」，點麥克風可以直接跳過等待。
3. **文字回覆沒有串流；語音有。** 客戶回覆本來就只有 1～3 句，文字串流實測只省 0.1～0.3 秒。
   但客戶的聲音用的是 **Gemini 真人語音的串流模式**（`gemini-3.8-flash-lite-tts`），
   第一段聲音約 1 秒就出來，邊收邊播。男客戶用 Charon、女客戶用 Aoede。
   任何原因失敗（額度、網路、服務商塞車）都會自動退回手機內建朗讀，演練不中斷；
   每回合約多用 340KB 行動數據。
4. **語音類評分依據有限。** 目前只有逐字稿與時間資訊，沒有音高／音量等聲學特徵，
   提示詞已要求模型不得假裝能精準判讀聲音（規格 §39）。
5. **合規詞庫是起點，不是法規全集。** `engine/compliance.js` 需依最新〈保險業務員管理規則〉
   與所屬公司規範持續校正。
6. **理賠建議只是初步判斷。** 系統只看你上傳的那份條款，不知道客戶實際投保的主約附約組合、
   保額、生效日與批註。實際理賠以保險公司核定為準。
7. **資料不跨裝置同步。** 文件與訓練紀錄都存在瀏覽器，換手機要重新上傳。
   清除瀏覽器資料也會一併清掉。

## 管理者報表（只有專案擁有者跑得動）

想知道有誰註冊、練了幾次、進步狀況：

```bash
node tools/report.mjs
```

產生兩個 CSV（含 UTF-8 BOM，Excel 與 Google Sheets 都能直接開）：

| 檔案 | 內容 |
|---|---|
| `AI業務教練_成員總表.csv` | 每人一列：姓名、E-mail、登入方式、註冊時間、最後登入、演練次數、最後演練、平均星等、五項能力各自平均、最常練的模式 |
| `AI業務教練_演練明細.csv` | 每次演練一列：時間、模式、客戶、五項分數、教練總結、下次挑戰 |

裝了 **Google 雲端硬碟桌面版**之後會自動寫進雲端硬碟資料夾，檔案跟著同步；
也可以自己指定：`node tools/report.mjs --out "G:/我的雲端硬碟/AI業務教練"`。
只要總表不要明細：加 `--no-detail`。

資料來源是 `firebase auth:export`（誰註冊）與 `firebase database:get /users`
