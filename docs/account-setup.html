帳號同步設定

做完之後，使用者就能用 Google 帳號或 E-mail 註冊登入， 訓練紀錄與偏好設定會跟著人跑，換手機、換電腦都接得起來。

這件事只有你（專案擁有者）需要做一次，而且只有你能做—— 要用你的 Google 帳號進 Firebase 後台。大約十分鐘。

在設定完成之前，App 完全正常運作，只是不會出現註冊／登入畫面。 這是刻意的：沒設定好就跳出一個壞掉的登入頁，比沒有登入頁更糟。

先講清楚會付出什麼

費用：Firebase 的免費方案（Spark）對一個業務團隊來說綽綽有餘—— Realtime Database 免費額度是 1GB 儲存、每月 10GB 傳輸，而我們一個人的資料 大概只有幾十 KB。不需要綁信用卡。

隱私：一旦開啟帳號同步，訓練紀錄與偏好設定會經過 Google 的伺服器。 README 原本寫的「沒有後端、不收集任何資料」在同步開啟後就不再完全成立， 這一點必須對同事說清楚。

不會上雲端的東西：API 金鑰、以及上傳的教材與保單條款， 一律只留在使用者自己的裝置。這是程式碼層面的限制，不是設定選項。

設定步驟

1

建立 Firebase 專案

開啟 Firebase 主控台 →

用你的 Google 帳號登入 → 建立專案 → 名稱隨意（例如 ai-sales-coach）。

中途問「要不要啟用 Google Analytics」時選「不要」。我們不需要， 而且開了就會開始收集使用者行為資料。
2

加入一個「網頁應用程式」，抄下 apiKey

專案首頁中間有一排圖示，點那個 </>（網頁）→ 取個暱稱 → 註冊應用程式。

接著會顯示一段 firebaseConfig 程式碼。只需要其中的 apiKey， 長得像 AIzaSy...，把它整串複製下來。

「不要設定 Firebase Hosting」——我們的網站放在 GitHub Pages。
3

開啟 Realtime Database，抄下網址

左側選單 建構 → Realtime Database → 建立資料庫。

  • 位置選 Singapore (asia-southeast1)，台灣連線最快
  • 安全規則先選 鎖定模式（下一步會換成正確的規則）

建好之後上方會有一行網址，長得像 https://你的專案-default-rtdb.asia-southeast1.firebasedatabase.app，複製下來。

4

設定安全規則（這一步最重要）

在 Realtime Database 頁面點 規則 分頁，把內容整段換成：

{
  "rules": {
    "users": {
      "$uid": {
        ".read": "$uid === auth.uid",
        ".write": "$uid === auth.uid"
      }
    }
  }
}

按 發布。

不要用「測試模式」的規則。測試模式是「任何人都能讀寫全部資料」， 等於把所有同事的訓練紀錄公開在網路上。上面這段規則的意思是： 每個人只讀寫得到自己那一份，別人的看不到也改不了。
5

開啟登入方式

左側 建構 → Authentication → 開始使用，然後在登入方式分頁啟用：

  • 電子郵件／密碼 — 直接啟用就好
  • Google — 啟用，並填一個「專案的公開名稱」（使用者授權時會看到）
啟用 Google 時 Firebase 會自動幫你建一組 OAuth 用戶端， 不必自己去 Cloud Console 建——但那組憑證預設不允許 GitHub Pages 的網址， 所以還有步驟 6。
Apple 先跳過。Apple 登入需要付費的 Apple Developer 帳號 （約 NT$3,300／年）才能申請憑證，這是 Apple 的規定。買了之後再回來啟用。
6

把網站網址加進 OAuth 用戶端的授權來源

啟用 Google 登入時，Firebase 已自動幫你建好一組 OAuth 用戶端。 但它預設只允許 firebaseapp.com，所以要手動把 GitHub Pages 的網址加進去。 建立 OAuth 用戶端與修改授權來源都沒有公開 API，這一步只能在網頁上點。

直接開啟這組憑證的編輯頁 →

在「已授權的 JavaScript 來源」按「+ 新增 URI」，填入：

https://zjh0511.github.io

要在本機測試就再加一行 http://localhost:8444。按儲存。

只填到網域就好，不要加 /ai-sales-coach/ 這種路徑—— JavaScript 來源只接受「協定＋網域＋通訊埠」，多填路徑會被拒絕。
存檔後 Google 那邊可能要幾分鐘才生效。生效與否可以這樣確認： 在網站的開發者工具主控台貼上 fetch('https://accounts.google.com/gsi/status?client_id=790589168231-ajsqtuoe7c7m3g185ilhokcqa447hd7v.apps.googleusercontent.com&as=x&origin='+encodeURIComponent(location.origin)).then(r=>console.log(r.status)) ——回 403 就是還沒生效，200 就是好了。
7

把三個值填進 firebase-config.js

編輯 docs/firebase-config.js：

export const FB = {
  apiKey: 'AIzaSy...',                                    // 步驟 2
  dbUrl: 'https://xxx-default-rtdb.asia-southeast1.firebasedatabase.app',  // 步驟 3
  googleClientId: '1234-abcd.apps.googleusercontent.com', // 步驟 6
  appleClientId: '',
  apple: false,
};

存檔 → commit → push。GitHub Pages 部署完成後，網站就會出現註冊／登入畫面。

這三個值是公開資訊，放進公開的原始碼是正常的，Google 的文件也是這樣寫。 真正的保護來自步驟 4 的安全規則。

常見問題

同事一定要註冊嗎？
要。登入是必經關卡，沒有「先不要登入」的出口——這是刻意的設計決定， 目的是讓每位使用者的訓練紀錄都跟著人跑。

萬一 Firebase 或 Google 登入掛掉，大家就都不能用了嗎？
是。這是強制登入的代價。緊急解法：把 docs/firebase-config.js 的 apiKey 清空再 push， 登入關卡就會消失，App 回到純本機模式（訓練紀錄仍在各自的瀏覽器裡）。 雲端已同步的資料不會消失，等問題解決把值填回去就恢復同步。

已經登入的人斷網還能用嗎？
可以。登入狀態存在瀏覽器，程式判斷的是這個本機狀態而不是去連線確認， 所以斷網不會把人鎖在外面（但演練本身要呼叫 AI API，那還是需要網路）。

我看得到同事的訓練紀錄嗎？
在 Firebase 後台可以（資料庫擁有者看得到全部資料）。這件事應該事先告知同事。 如果不希望自己看得到，就不要開啟帳號同步。

API 金鑰會被同步嗎？
不會。金鑰與上傳的文件寫死在程式碼裡不上傳，只有訓練紀錄與偏好設定會同步。 所以每台新裝置第一次還是要貼一次金鑰，之後就記住了。

免費額度會不會爆掉？
一個人的紀錄大約幾十 KB，上限是每人 100 筆。就算五十個同事都在用， 離 1GB 還很遠。真的接近了 Firebase 會先寄信通知。

想關掉帳號功能怎麼辦？
把 firebase-config.js 的 apiKey 清空再 push， 登入畫面就會消失，App 回到純本機模式。已同步的資料還在雲端，不會消失。
