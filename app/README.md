## 架構

程式邏輯與 AI 生成分離——狀態由程式控制，模型只負責語言（規格 §95）。

```
public/            瘦客戶端：UI + 語音，不含任何教練邏輯
  app.js           六大功能的畫面流程
  voice.js         Voice Engine（STT/TTS 抽象層，可整檔替換 Provider）
lib/               伺服器端（核心 IP 不下發到瀏覽器）
  gateway.js       Model Gateway：模型探測、重試、過載自動降級
  prompts.js       分層提示詞：Base → Mode → Persona → State → Turn
  session.js       Coach Engine 狀態機（三種角色扮演模式）
  advisor.js       痛點分析／理賠諮詢／行銷諮詢
  knowledge.js     Knowledge Engine：文件 → 結構化知識庫
  docx.js          極簡 ZIP+XML 解析（.docx/.pptx，零外部相依）
  compliance.js    Compliance Engine（規則優先，不依賴 LLM 判斷）
server.js          HTTPS/HTTP 伺服器 + API
data/              上傳的文件與知識庫（本機，不進版控）
```

### 文件解析策略

| 格式 | 做法 |
|---|---|
| `.docx` / `.pptx` | 本機解 ZIP 讀 XML 取字（Node 內建 zlib，不裝任何套件） |
| `.pdf` | 直接把原始檔交給模型讀，中文與掃描版都比自寫解析器可靠 |
| `.txt` / `.md` | 直接讀 |
| `.doc` / `.ppt` | 不支援，請另存成新格式或 PDF |

上傳時會做一次「知識結構化」（規格 §41），之後查詢用摘要即可，不必每次重送整份文件。
理賠查詢因為準確度要求高，會回頭比對條款原文。

### 接觸情境與話術資訊邊界

演練前要先選「接觸情境」，這決定了業務員**此刻合理知道客戶什麼**，示範話術只能在這個邊界內設計。

| 情境 | 業務員知道的 |
|---|---|
| 陌生開發 | 只有稱呼，可能連這個都不確定 |
| 客戶轉介紹 | 介紹人是誰，加上介紹人隨口提過的表層資訊 |
| 緣故 | 彼此關係與生活近況，但不含財務細節 |
| 既有客戶服務 | 過去成交紀錄與對方主動說過的事 |
| 之前談過沒成交 | 上次的主題與當時的顧慮 |
| 活動後追蹤 | 參加過哪場活動 |

`prompts.js` 的 `demoLeaksPrivateInfo()` 會掃描產生出來的示範話術，
若在陌生／轉介紹／緣故／活動後情境中出現保額、保單、繳費金額等字樣，**自動重新產生**。

角色扮演的客戶也知道這層關係——你若講出他沒說過的私人資訊，他會反問「你怎麼會知道？」並提高防備，
評分時也會被列為改善點。

### 建立信任感（NLP）

示範話術與教練回饋都遵循 `RAPPORT` 七原則：先跟後帶、語言同步、尊重自主權（給對方退路）、
開場交代「我是誰／為什麼是現在／為什麼是你」、先處理情緒再處理事情、第一次接觸只求一個小承諾、
問句從生活出發而非從錢出發。依規格 §53，明文禁止用於操控、製造恐懼或假裝熟識。

### 話術中立化

系統產生的示範話術一律不預設保險公司：公司寫「○○人壽」、人名寫「○○」、
自我介紹統一為「○○人壽的○○」。提示詞層先要求，`prompts.js` 的 `scrubBrands()` 再做一道程式層過濾。

**不套用**於逐字稿、評分證據（使用者自己說的話）、以及上傳的條款與商品教材（本來就有真實名稱）。

**投影片如果大多是圖片，取到的字會很少**——系統會直接警告你，並建議改用 PDF 上傳。

**API Key 不會進入前端。** 瀏覽器只跟本機伺服器對話，金鑰留在 `server.js` 這一端。

### 換模型 / 換語音

- 換 LLM：在 `lib/gateway.js` 新增一個具備相同 `generate()` 介面的 adapter。
- 換 STT/TTS：整份替換 `public/voice.js`，App 其他部分不需修改。

## 已知限制（誠實列出）

1. **本機模型尚未接上。** 目前走 Gemini API。iPhone Safari 分頁記憶體約 1～1.5GB，跑不動 Gemma 3n E2B（量化後仍需 2～3GB）；真正的裝置端推論必須等原生 iOS App 階段。Gateway 介面已預留。
2. **Barge-in 是「點擊打斷」而非自動偵測。** iOS Safari 無法在 TTS 播放時穩定同時收音，V1 以點麥克風打斷代替。
3. **未做 Streaming。** 客戶回覆本來就只有 1～3 句，先求穩定；`gateway.js` 結構允許之後改 SSE 串流。
4. **語音類評分依據有限。** 目前只有逐字稿與時間資訊，沒有音高/音量/語速等聲學特徵，所以「聲音親切感」是從文字表現推論的，提示詞已要求模型不得假裝能精準判讀聲音（規格 §39）。
5. **合規詞庫是起點，不是法規全集。** `lib/compliance.js` 需依最新〈保險業務員管理規則〉與所屬公司規範持續校正。

6. **理賠建議只是初步判斷。** 系統只看你上傳的那份條款，不知道客戶實際投保的主約附約組合、保額、生效日與批註。回覆一律附免責聲明，實際理賠以保險公司核定為準。

## 實測數據（2026-08-16）

| 項目 | gemini-3.7-flash | gemini-3.5-flash-lite |
|---|---|---|
| 建立客戶 Persona | 4.6 秒 | 4.9 秒 |
| 角色扮演每回合（LLM） | 2.3～2.8 秒 | **1.0～1.2 秒** |
| 五項評分 | 10.8 秒 | 4.4 秒 |

flash-lite 已達成規格 §29 的 ≤2 秒目標，且 1～3 句的客戶回話品質足夠。
Gateway 會自動依可用額度與延遲選模型。環境變數可覆寫：

```bash
SPEED=1 node server.js                      # 角色扮演優先用最快的模型
MODEL=gemini-3.5-flash-lite node server.js  # 全部鎖定單一模型（比較用）
```

全程鎖定 `gemini-3.5-flash-lite` 實測：自我測試 40 項全過，角色扮演 989ms、建立客戶 3.8 秒、評分 4.2 秒。
