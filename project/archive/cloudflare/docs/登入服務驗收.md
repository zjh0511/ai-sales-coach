已完成：登入憑證自動更新（當前瀏覽器分頁）、登入錯誤分類、舊帳號密碼長度相容、重寄驗證信、Google 憑證交給原 Firebase 驗證。本機測試身份與真實 Firebase 身份仍隔離，測試 Key 不會自動搬到正式帳號。

18 項自動測試通過。原專案 accounts:createAuthUri 對 localhost 與 127.0.0.1 都回應 HTTP 200，但這不代表 Google OAuth 網址已獲授權。

## 目前確認的外部阻擋

Google 按鈕實測回報：`The given origin is not allowed for the given client ID.`

請在原 Google Cloud 專案「API 和服務 → 憑證」，開啟目前使用的 OAuth 2.0 網頁用戶端（Client ID 與 config.local.json 的 googleClientId 相同）。在「已授權的 JavaScript 來源」新增：

```
http://127.0.0.1:8787
http://localhost:8787
```

保留所有舊來源與重新導向網址。不要建立新用戶端。這兩筆是 JavaScript 來源，沒有結尾斜線，也不是填入重新導向 URI 欄。

[開啟原專案憑證設定](https://console.cloud.google.com/apis/credentials?project=ai-sales-coach-4b4cb)

保存生效後，重新整理本機登入頁，由本人完成一次 Google 登入，再確認頁面顯示真實帳號、可保存 Key，重整後仍可使用。真人 Google 登入與 E-mail 寄信驗證尚未完成，不應標記整套登入已驗收。

## Chrome 來源缺少埠號：已定位及修正
使用者按重新連線後的實際請求：Origin=http://127.0.0.1，Host=127.0.0.1:8787，Sec-Fetch-Site=same-origin。來源缺少埠號，原本因此回傳 ORIGIN 403。原因已定位到收到的請求標頭差異，尚未判定是瀏覽器或中間軟體造成。
本機轉接器只在 Host 為允許的本機位址、Origin 精確等於該主機不含埠號、Fetch Metadata 為 same-origin 時補回埠號；雲端不套用。20 項測試通過，包含其他來源、不同埠號、null、缺少或非同源 Metadata 不會被放行。已移除臨時診斷記錄。Chrome 真實帳戶登入待使用者再按重新連線驗證。
