## 1. 建議決策摘要

建議製作「手機優先、可加入主畫面的 PWA 網頁 App」，以電話約訪為第一條完整訓練流程，再完成需求探索、商品演練、客戶分析與專業討論。前端部署 GitHub Pages，另搭配小型受控後端，處理金鑰、試用資格、教練核心、官方查核及評分。

保留 GPT 的教學風格、示範、角色互換與鼓勵式回饋；新增獨立 App 能做到的固定流程、即時攔截、教材來源追溯、紀錄、同情境重練及前後比較。

四項需求的可行性判斷：

| 要求 | 判斷與建議 |
|---|---|
| 網頁版放 GitHub Pages | 可承載靜態前端；AI 金鑰與受保護功能另放後端。正式商業服務需另評估主機與使用條款。 |
| ChatGPT 帳號登入並用本人額度 | 本次未查得可供此類第三方保險 App 普遍使用的官方授權方案；不列為已可實現的功能。建議 Google／Email 登入 App，試點由你提供受控 API 額度。 |
| 免費、台灣語調語音 | 優先驗證 Azure Speech F0 的 zh-TW 辨識及 HsiaoChenNeural／YunJheNeural 朗讀；屬有限免費額度。瀏覽器語音作低成本備援。不能承諾免費無限、跨裝置一致或完整聲音評分。 |
| 輕量程式 | 不把大型語言或語音模型下載到手機；前端按功能載入，重運算交給後端。小容量不等於零依賴或零營運成本。 |

本企畫不承諾「全部免費且具備 ChatGPT 等級即時語音與完整五星評分」。免費語音可先試點；完整音訊評分必須另完成概念驗證與成本核算。

## 3. 產品定位與使用流程

定位：讓保險業務員在見客戶之前，能反覆準備、練習、修正，並看見可觀察的進步。

主要循環：設定情境 → 先看範例 → 選擇角色 → 語音演練 → 即時指正 → 五項回饋 → 同情境重練 → 比較改善。

首頁建議呈現「今天要練什麼？」；主要入口為電話約訪、需求探索、商品行銷，另設客戶準備、問教練、我的練習。手機直式優先，字體可放大，麥克風狀態、目前角色與停止鍵持續可見。

## 4. 五大功能規格

### 4.1 客戶潛在痛點分析

只提供性別、年齡、背景三類欄位；允許未知及不完整背景。每次輸出三項「待驗證需求假設」，各含已知依據、不確定性、接觸開場與探索問題。背景不足時給三個探索方向，不虛構職業、家庭或財務事實；不單憑性別或年齡判定購買能力。

禁止圖片選取、貼上及拖入；背景中的姓名、電話、身分證、住址、保單號等先攔截。結果可帶入下一場需求探索，但假設不轉成已確認的客戶事實。

### 4.2 電話約訪語音演練

輸入客戶關係、邀約目的、非識別背景、預想拒絕與難度，先提供邀約範例及注意事項。支援「我當業務、AI 當客戶」與「我當客戶、AI 示範業務」；角色交換由使用者操作。

第一版採輪流說話，可按鍵結束本句及停止播放。AI 回應前先檢查違規風險；結束後回饋，再用同一情境練習。邀約成功並非唯一標準，不獎勵施壓。示範模式提供教學拆解，不把 AI 的表現算成使用者分數。

### 4.3 發掘需求角色扮演

保留你指定的「用戶扮演客戶」作示範模式；另建議加入「用戶扮業務、AI 扮客戶」作能力訓練。預設哪個模式待你確認，不能默默改寫原意。

AI 客戶具有背景、隱藏需求與逐步揭露條件，由程式控制目前角色、信任狀態、已揭露資訊及結束條件。先給通用提問示例，不洩漏本場隱藏需求。評估是否傾聽、追問與確認，而非猜中答案。

### 4.4 商品行銷演練

先完整處理公版教材，再產生賣點、客戶利益、限制及話術。每項商品主張對應文件名稱、版本、頁碼／段落及原文；未載明條件不靠模型補足。

首輪建議支援文字型 PDF 與 TXT，暫定每份 10 MB、100 頁以內，這是待實測的範圍建議。DOCX／PPTX 列入後續擴充；掃描檔、加密檔、無法解析的表格明確報錯或標示缺口。不得截取前幾頁就宣稱完整閱讀。全文件解析與涵蓋檢查通過後才建立摘要；檢索負責回答時找證據，不能取代完整處理。

教材入口同樣拒絕客戶個資文件與截圖；第一批建議由你審核公版教材。混入個資或無法確認內容的檔案暫停處理。AI 演練必須核對保障、除外責任等原文，不自行承諾理賠或報酬。

### 4.5 AI 業務教練討論

保留業務招攬、客戶溝通、理賠疑問、稅務與法律問題入口。專業內容先查來源；理賠採條款閱讀、可能相關條件、缺少資訊及向公司確認清單，不作核賠判定。一般問題同樣遵守下述先查核要求，不自行刪除你的需求。

## 5. 共同核心：個資、查核與自律指正

### 5.1 個資保護

前端先檢查輸入、後端再次驗證，涵蓋背景、聊天、轉錄與教材；結合格式規則及語意檢查，不宣稱能百分之百識別個資。少量背景組合仍可能識別某人，提示使用概括描述及合成人物。

啟用雲端辨識前明示音訊會傳至服務商；轉錄後遮罩無法追回先前送出的音訊，不可宣稱語音已完全阻止個資外傳。原始教材、音訊、逐字稿不進一般錯誤日誌；帳號身份與客戶背景分開處理。

建議試點原始音訊僅供當次評估，App 處理完成即刪除，逾時清理上限暫定 24 小時；服務商保留政策另行查核揭露。練習摘要暫定保存 90 天，可提前刪除；教材可主動刪除。期限均為待確認建議。

帳號 A／B 的裝置快取、文件、歷史及雲端權限完全隔離。登出清理記憶體；資料逐筆存放，避免整包覆蓋。刪除須涵蓋雲端及離線重連，不能讓舊資料復活。PWA 離線快取限程式外殼，不快取敏感 API 回應或金鑰。

### 5.2 回答前官方查核

依你的要求，所有實質教練問答在回答前執行全國法規資料庫查詢；不預先豁免一般溝通問題。純虛構客戶回應不視為專業結論；其中若涉及法規、商品事實，仍先查核。此界線沿用 Sol 藍圖，待產品確認。

流程：去識別問題 → 找適用法規 → 取得官方正文 → 核對條號、版本與適用日期 → 比對答案主張 → 顯示引用與查核時間。搜尋摘要和模型自稱已查詢不能過關。

若成功查詢但沒有直接適用法條，清楚標示以下為教學建議，無法條背書。若查詢失敗、逾時或正文無法讀取，暫停實質回答並提供重試；不能以模型記憶或過期快取冒充本次查核。

全國法規資料庫是必要起點；實際專業問題可能還需主管機關公告、函釋、同業公會自律規範及公司版本。官方網站也有更新時間差；答案顯示資料截止／更新日期，不能把當天查詢等同當天完整法規。[全國法規資料庫](https://law.moj.gov.tw/)

工程先驗證官方取得方式、連線限制、更新及服務規範，不假設有任何可直接使用的搜尋 API。引用驗證可檢查文字與定位，法律適用性仍需專家基準檢驗，不能宣稱程式可保證所有法律推論正確。

### 5.3 即時自律規範指正

最低標準：本句辨識完成後，AI 客戶下一次正常回應前介入。不是到事後評分才提醒，也不宣稱已達語音中途毫秒級打斷。

處理：凍結情境 → 顯示原句 → 區分明確違規／待確認疑慮 → 查核並說明依據 → 提供替代表達 → 學員重說 → 恢復原角色。查核中可先顯示「正在核對，演練已暫停」，不先宣判違法。

規則由已確認的自律規範及公司政策建立，保存來源、版本、適用範圍、正反例與維護人。規則比對加語意判讀；否定句、引用別人的話及轉錄錯誤須測試。若檢查服務失效，暫停演練，不靜默繞過。合規事件單獨呈現，不被平均星等掩蓋。

## 6. 語音選型與五星評分

語音需拆成四件事：聽懂語音、生成對話、把回應念出來、評估聲音。前後兩者不是同一模型，免費朗讀不代表 AI 推理與評分也免費。

| 方案 | 適合用途 | 限制與決策 |
|---|---|---|
| Azure Speech F0：zh-TW STT；HsiaoChenNeural 女聲／YunJheNeural 男聲 | 第一優先的台灣華語試聽與辨識驗證 | 官方列出台灣華語；F0 每月即時轉錄 5 小時、神經朗讀 50 萬字元，額度以實際資源／方案為準，不是每位 App 學員各一份。需 Azure 資源，超限停止或明示切換，不自動付費。 |
| Web Speech：SpeechRecognition + speechSynthesis | 無另接計費語音 API 的輕量備援 | 設 zh-TW，列舉實機聲音供試聽；不保證每台有台灣聲音。辨識支援度有限且部分會送雲端，不承諾永久免費服務或離線運作。 |
| 自架開源語音模型 | 日後特定組織的研究選項 | 授權、主機及 GPU 成本需另算；不列第一版，不把大模型包入 PWA。 |

來源：[Azure 語言與音色](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts)、[Azure F0 價格](https://azure.microsoft.com/en-us/pricing/details/speech/)、[MDN 辨識](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[MDN 聲音清單](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)。台灣自然度仍需真人盲聽，不因 zh-TW 標籤就宣稱最好。

免費額度量級示例：若每場送出學員音訊 5 分鐘，300 分鐘約供 60 場；20 人每人 3 場即可能用完。這只是除法估算，不是服務可用性或試點總成本保證。

五項評分固定如下，每項滿分五顆星：

| 項目 | 證據 |
|---|---|
| 說話流暢度 | 音訊語速、停頓、連貫性及逐字稿；不能單靠文字判斷全部聲音表現。 |
| 聲音語調的親切感 | 實際音訊中的語調、節奏與互動；不以音色或口音好惡評分。 |
| 客戶談話的內容掌握 | 對話中的回應、追問、摘要與確認。 |
| 用戶的自信心 | 本次可觀察的表達與應對；不推斷內在人格或心理狀態。 |
| 用戶的專業度 | 內容正確、來源、限制說明、需求適配與合規事件。 |

音訊評估另做早期 PoC：同意後取得音訊、分離學員與 AI 播放、分析時間及聲學特徵，搭配能讀取音訊的評估服務候選，再由你與講師校準。音高／音量數值不能直接換算親切感；語音辨識或發音評分也不能直接當業務五星評分。此引擎與價格尚未選定，是 V1 的發布關卡。

所有五欄都顯示，音訊不足者標「無法評估」，不能補星數；只有文字回饋的版本叫 Alpha，不能宣稱完整 V1。示範場次只做示範拆解。

回饋順序：先肯定具體亮點及證據 → 五項星等及理由 → 最值得改善的一件事 → 可直接重說的版本 → 合規修正狀態 → 再練一次。星等初定 1 需大量引導、2 部分達成、3 基本達成、4 穩定達成、5 高品質且有證據，行為尺度由講師定版。

## 7. 登入、部署與輕量架構

### 7.1 帳號與額度

OAuth／OIDC 登入是身份認證，不等於 AI 使用額度授權。OpenAI 官方一般 API 文件使用 API 憑證；ChatGPT／Codex 的訂閱登入有其產品適用範圍，不能據此推定第三方 App 可扣用 ChatGPT 訂閱額度。本次未找到此保險 App 的通用官方方案，故保留研究項，不列入 V1 承諾。[OpenAI API 認證](https://developers.openai.com/api/reference/overview)、[官方登入說明](https://learn.chatgpt.com/docs/auth)

建議 Google 登入或 Email 登入 App，後端再核對測試名單。你提供的測試金鑰只存受控後端；不要求同事先申請金鑰。日後可另設使用者自付 API 的方案，但那也是 API 帳戶費用，不是 ChatGPT 額度。不收 ChatGPT 密碼、Cookie 或訂閱權杖作替代。

### 7.2 架構與分工

資料流：手機／電腦 PWA → 身份與試點資格驗證 → 教練後端 → AI／語音服務、官方查核、受權限保護的紀錄儲存。

| 層 | 工作 |
|---|---|
| GitHub Pages 前端 | 畫面、麥克風控制、輸入初檢、進度呈現、安裝外殼。 |
| 小型後端 | 金鑰、資格、配額、角色狀態、核心提示、查核、教材解析與評分協調。可用 serverless 或小型服務，依 PoC 定版。 |
| 帳號與資料 | 優先評估延用舊專案 Firebase；若原始碼不適合再選替代，不先綁定新服務。 |
| 模型介接 | 對話與評分分工，保存實際模型與規則版本；模型名稱待實測、品質和成本比較後選定。 |

GitHub Pages 只提供靜態託管，不承載這些後端機密與處理。發布時只上傳前端產物白名單，絕不能將專案根目錄整包發布，避免 API Key.txt 與內部 MD 被公開。標準 API Key 不進前端或 localStorage。[GitHub Pages 說明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[OpenAI 金鑰保護](https://developers.openai.com/api/reference/overview)

Pages 並非正式商業 SaaS 的免費主機方案；本企畫限初期展示／同事功能測試，發布前核對具體用途，商業化前改用適合的託管服務。[GitHub Pages 使用限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

### 7.3 容量與安全預算

建議首屏必要 HTML／CSS／JS 壓縮傳輸合計不超過 300 KB，離線外殼不超過 2 MB；為待驗證目標，外部登入／語音 SDK 另列並量測完整首訪成本，不用排除項目掩飾體積。

使用系統中文字型、小型 SVG 圖示、按需載入文件功能，避免影音首頁與大型 UI 套件；重型解析放後端。開發工具大小與同事實際下載大小分開看，必要依賴鎖版管理。離線可看外殼與已允許的紀錄，不能離線產生未查核的專業答案。

後端每次檢查身份、資料所有權及配額；來源網域限制不是身份驗證。加入大小限制、速率限制、輸出安全呈現、教材提示注入防護與秘密掃描。核心提示及隱藏需求留後端，不依賴 JavaScript 混淆保密。

## 9. 成本管理

總成本包括文字生成、官方查詢、教材解析、語音輸入／輸出、音訊評分、後端與儲存。Pages 免費或語音 F0 不代表整套 App 免費。此階段未調用測試 API，尚無實測單場成本。

試點容量假設：20 人 × 每週 3 場 × 4 週 = 240 場。月估算 = 240 × 實測每場成本 + 文件處理 + 主機／儲存 + 預留重試成本。階段 A 跑代表案例，記錄 token、音訊分鐘、查詢次數及失敗重試，再填單價估算。

建議試點月上限先討論 NT$1,000～3,000，這是可選管理預算，不是報價或支出授權。後端必須有每人與全站硬性額度、併發預留及超額停止；通知不能替代限流。免費資源用完不自動升級付費語音。正式測試前確認上限再使用測試金鑰。
