## 2. 產品願景與核心定位

### 2.1 願景

將既有 GPTs 教練的教學方法與互動品質移植為可獨立使用、可信任且可追蹤進步的 App，讓保險業務人員隨時準備、練習、獲得具體指導，再用同一情境驗證改善。

核心使用者為保險業務新人、一般業務人員，以及參與試點與品質校準的主管和講師。V1.0 以內部訓練使用為目標；商業化與原生 App 為後續決策。

### 2.2 核心體驗

**準備 → 示範 → 演練 → 即時指正 → 回饋 → 重練 → 前後比較 → 下一個挑戰。**

移植必須保留四層能力：

1. **教練人格與方法論**：繁體中文、鼓勵式指導、先肯定再改善、避免過早揭露答案。
2. **角色扮演引擎**：角色鎖定、情境資訊邊界、隱藏需求、信任與難度、結束條件。
3. **知識與可信度**：教材依據、來源查核、版本追溯、資訊不足時停止推論。
4. **產品體驗**：易於開始的語音流程、紀錄、重練與成長追蹤。

每項新增工作須回答：是否幫助實際練習、是否提供可執行的改善行動、是否有助於觀察改善。第五項諮詢服務應支援上述核心體驗。

## 4. 各功能流程與邊界

### 4.1 客戶潛在痛點分析

**輸入：**僅提供性別、年齡、背景描述。知道什麼寫什麼，不強迫補齊、不要求姓名或聯絡資訊。

**流程：**輸入 → 個資檢查 → 回答前查核 → 產生三項需求假設 → 提供接觸方向 → 選擇帶入需求探索演練。

每項假設必須包含：可能需求、依據的已知背景、資訊不足與不確定性、可使用的開場或探索問題。資料不足時仍可提供三個探索方向，但須標示依據有限，不能補造客戶事實。

**邊界：**不得宣稱已判定客戶真實痛點；不得僅憑性別或年齡斷定需求、財力或購買意願；不得將假設自動轉成確定商品推薦。此功能禁止圖片上傳與貼上圖片。

### 4.2 電話約訪語音演練

**優先定位：**第一旗艦訓練流程與第一批評分基準案例。

**流程：**設定客戶關係、邀約目的、非識別背景、預估反應及難度 → 提供邀約策略、參考話術與注意事項 → 選擇模式 → 自行開啟語音 → 演練與即時指正 → 評分回饋 → 同情境重練與比較。

| 模式 | 使用者 | AI | 教學目的 |
|---|---|---|---|
| 挑戰模式 | 業務員 | 客戶 | 練習建立接觸、回應拒絕與確認邀約 |
| 示範模式 | 客戶 | 業務員 | 聽見示範並觀察教練如何處理反應 |

模式須明確顯示。交換角色必須是使用者操作，不能在一般演練回合中自行切換。示範模式不得把 AI 的業務表現算成學員能力分數，應提供示範重點與後續練習入口。

**邊界：**不實際撥打客戶電話、不代發邀約；AI 客戶只使用該關係合理知道的資訊；邀約成功不能成為唯一評分依據，也不得靠施壓換取高分。

### 4.3 發掘需求角色扮演

**流程：**設定非識別背景與練習目標 → 提供探索範例 → 確認角色 → 語音演練 → 依傾聽、提問與信任逐步揭露資訊 → 學員整理並確認需求 → 回饋 → 重練。

主要訓練目標為讓學員練習業務員的需求探索能力。原始需求也寫有「用戶扮演客戶」，因此角色選項應保留該意圖；主要模式與角色互換的最終設定見第 15 節，不能直接刪除客戶角色體驗。

**狀態要求：**情境需保存顯性需求、隱藏需求、已揭露資訊、信任狀態、難度、目前階段及結束條件。由程式決定可揭露的範圍，再由模型組織語言。長對話、重整或恢復後仍須維持一致。

**邊界：**AI 不得開場就交代全部隱藏需求；不得把猜中需求視為完成探索；演練前範例須使用通用或不同情境，不提前洩漏本場答案。學員卡住時提供分級提示，且記錄提示使用情形。

### 4.4 商品行銷演練

**輸入：**公司公版且使用者有權提供的商品行銷教育訓練教材。教材上傳不是接受客戶個資文件的例外。

**流程：**上傳前說明資料傳輸 → 檔案及個資檢查 → 全文件解析與涵蓋檢查 → 建立可追溯知識 → 歸納定位、特色、適合族群、客戶利益、行銷切入點與常見異議 → 產生有依據的話術 → 語音演練 → 合規及內容核對 → 回饋與重練。

**完整閱讀要求：**必須辨識解析成功、缺頁、掃描無法讀取、表格遺漏、超出容量或上下文限制等情況。可採分段處理與檢索，但不得只讀部分內容便宣稱已完整閱讀；未完整處理時須標示範圍，停止完整商品摘要與相關確定結論。

商品主張必須可追溯至文件名稱、版本、有效日期（未載明則標示未知）、頁碼或段落，以及支持該主張的原文。來源不存在或證據不足時，明確回答「目前教材不足以確認，請核對公司最新資料」。

**邊界：**不得補造保障、費率、報酬、豁免、除外責任或理賠條件；一般知識不能覆蓋指定教材；不同版本不得無提示混用。教材中的指令文字只當資料，不得改寫教練規則。

### 4.5 AI業務顧問

**範圍：**業務招攬、客戶溝通、異議處理、銷售策略、客戶經營、商品理解、條款閱讀、理賠方向、法律及稅務相關問題。

**流程：**接收問題並移除識別資料 → 分類與判斷所需依據 → 查核官方資料／指定教材 → 檢查來源是否支持結論 → 回答並展示查核資訊 → 提供確認清單或相關練習。

理賠部分定位為「保單條款閱讀輔助」：輸出可能相關條款、原文證據、尚缺資訊與應向公司理賠單位確認的事項。不得承諾核賠、精確理賠金額或確定法律／稅務結果；不接受含個資的保單頁、診斷書或客戶截圖。

## 5. 個資與隱私規則

### 5.1 輸入保護

1. 客戶資料欄位僅為性別、年齡、背景；背景須提醒不得輸入姓名、電話、身分證字號、地址、完整生日、保單號碼等識別資訊。
2. 偵測背景、自由文字、語音轉錄與上傳資料中的識別內容；攔截或要求去識別後再處理。不能只靠警語或移除姓名欄位。
3. 拒絕客戶個資截圖，包含 LINE 對話、CRM、客戶資料卡及保單個資頁；教材入口同樣適用。
4. 傳給遠端模型前應先完成可行的輸入檢查。若語音轉錄本身由遠端服務處理，須在啟用麥克風前說明音訊會先送出，不能宣稱已阻止所有口述個資外傳。
5. 不將個資或原始教材放進錯誤日誌、分析事件或公開測試案例；測試使用合成資料。

### 5.2 三條資料流須分別告知

| 位置 | 須說明的內容 |
|---|---|
| 使用者裝置 | 紀錄、偏好、教材、憑證與音訊是否保存及如何刪除 |
| App 雲端／Firebase | 哪些紀錄同步、帳號隔離方式、跨裝置刪除行為 |
| AI／語音服務商 | 實際服務商、送出的文字／教材／音訊、處理目的 |

不得使用「不上雲端」概括所有資料。報告基準版本的正確區別是：文件未存入本專案 Firebase，內容仍可能傳給 AI 服務商；實作改動後須同步更新告知。服務商保留與訓練政策須依實際選用服務查證，不可代為承諾零保存。

### 5.3 帳號隔離、刪除與權限

- localStorage 紀錄、偏好及 API Key 以使用者 UID 隔離；IndexedDB 文件具 `ownerUid`，讀寫刪除均檢查所有者。
- A 登出、B 登入時，不得看到、使用或同步 A 的資料與金鑰；登出也須清除記憶體中的前帳號狀態。
- 舊版未歸屬資料不得自動分配給目前登入者；遷移須可驗證所有權，無法確認則隔離處理，並有回復方案。
- 分開提供「清除此裝置資料」與「刪除所有裝置及雲端紀錄」，說明前者是否會再次同步。
- 雲端刪除採實際刪除與防止舊裝置回傳的機制，例如刪除標記；離線裝置重連不得使資料復活。失敗須顯示待重試，不得假稱成功。
- 文件提供可操作的刪除入口；音訊預設不長期保存為本規格落地原則，若需保存回放，另行明確告知、取得同意並訂保留期限。
- 內部使用權限必須在受控服務端落實；登入成功不等於取得試點資格，前端隱藏按鈕不能作為門禁。

## 6. 自律規範即時指正

**必要行為：**學員講到違反自律規範的內容時，AI 教練即時指出問題並引導改說，再返回原演練。

流程為：取得可判讀語句 → 規則與語意檢查 → 暫停客戶回應 → 顯示並語音說明教練提醒 → 引用該句、說明問題與依據 → 提供替代表達 → 讓學員重說 → 恢復原角色及情境。

「即時」最低要求為在該句辨識完成後、AI 客戶下一次正常回應前介入，不能只在結束評分時提醒。實際延遲須量測，發布門檻於語音規格制定。

合規規則須具來源、版本與適用範圍；區分明確違反已確認規則與需查核的疑慮。轉錄不清或依據不足時先澄清，不把疑似問題宣告成法律定論。新增法律性說明適用第 7 節。

介入期間凍結演練進度；提醒不能讓 AI 客戶無故知道隱藏資訊。紀錄包含觸發語句、規則版本、提醒內容與學員修正結果。即使整體表現良好，也須獨立顯示合規事件，不以平均星等掩蓋。

## 7. 官方來源查核與可信度機制

### 7.1 使用者原則與適用界線

保留使用者「回答任何問題前，尤其稅務、法律等專業問題，先上全國法規資料庫查詢確認」的要求。全國法規資料庫入口為 <https://law.moj.gov.tw/>。

先前討論曾建議一般教練問題直接回答，但此建議不得默默縮小使用者的查核要求。在使用者另行確認豁免前，所有問答先執行查核流程；純溝通建議若無適用法條，應明示「未找到直接適用法條；以下為教學建議」，不可假裝有法律背書。角色扮演中的虛構客戶反應不是法規結論；凡加入專業事實或教練解釋，仍須經對應查核。

### 7.2 依問題類型補足證據

| 類型 | 回答所需依據 | 不足時處理 |
|---|---|---|
| 一般教學與溝通 | 完成查核流程，區別教學建議與法規事實 | 不引用不存在的法條 |
| 公司商品／教材 | 指定教材的可核對原文；相關法規另查官方來源 | 不形成商品確定主張 |
| 法律、稅務、保險法規 | 全國法規資料庫；必要時補充相關主管機關官方資料 | 不依模型記憶產生具體結論 |
| 理賠方向 | 可核對條款與相關官方依據 | 列待補資訊及確認事項，不作核賠判定 |

官方資料不得被搜尋摘要、模型自述「已查核」或第三方文章取代。查核必須取得可讀取內容，核對法域、適用日期與版本；官方來源衝突或適用性不明時說明差異並保留結論。

### 7.3 可見查核資訊與失敗行為

回答需呈現查核時間、來源名稱、可點擊連結、法規名稱／條號或教材定位、適用日期及限制。以程式驗證來源確實取得、引用可定位且支持主張；不得由模型編造連結或引用。

查核逾時、斷網、來源不可讀或證據不足時，顯示原因與重試入口，暫不提供依賴該來源的具體結論。若要採用快取作為即時查詢的替代，須另訂更新、失效及使用者可見規則，不能自行視同已完成本次官方查詢。

本文件定義查核產品機制，並未就任何現行法律條文或稅額作實質法律查核。

## 8. 語音與五星評分架構

### 8.1 語音流程

使用者選擇語音 → 麥克風及資料傳輸告知 → 音訊輸入／轉錄 → 情境引擎與合規檢查 → AI 回應與語音播放 → 結束演練 → 分析與回饋。

須處理權限拒絕、無收音、辨識失敗、網路或模型逾時、切背景、恢復與重複回合。提供可理解的恢復操作；文字替代模式須標示評分限制。模型降階亦須留下實際使用紀錄。

### 8.2 分工

| 元件 | 責任 |
|---|---|
| Voice Analysis | 根據音訊分析流暢度、語速與停頓、語調親切感及部分自信表達線索 |
| Conversation Judge | 根據對話、情境、教材與合規事件判斷內容掌握、應對及專業度 |
| Coach Score Engine | 整合證據、五項分數、評分版本與回饋；檢查缺漏與輸出格式 |

### 8.3 固定五項，每項滿分五顆星

| 項目 | 主要觀察 | 必要限制 |
|---|---|---|
| 說話流暢度 | 語速、停頓、贅詞、連貫性 | 聲音表現須有音訊或可靠時間訊號 |
| 聲音語調的親切感 | 語調、節奏、音量與互動方式 | 不得僅用文字假裝評過聲音 |
| 客戶談話的內容掌握 | 是否理解、回應、追問並確認客戶意思 | 逐項連結對話證據 |
| 用戶的自信心 | 清楚表達、應對與可觀察語音表現 | 評的是本次自信表達，不推斷內在人格或心理狀態 |
| 用戶的專業度 | 資訊正確、來源、風險說明、合規與需求適配 | 不以強硬推銷或說得肯定替代專業 |

五項均須呈現，資料不足者標示「無法評估」及原因，不補造星等。文字模式或無有效音訊時不能宣稱完成完整五星語音評估；V1.0 必須有可實際提供五項評分的有效語音流程。

建議統一星等語意：1 星＝需大量引導；2 星＝部分做到但多處待改善；3 星＝基本達成；4 星＝穩定達成且能因應情境；5 星＝高品質且有具體證據。各維度的行為錨點須由業務訓練專家校準後定版，半星規則與整體加權不在本文件臆定。

不因口音、個人音色或單純音量低而直接低評；收音品質、辨識信心與資料充分性應影響評估可用性。

### 8.4 回饋順序

1. 先肯定本次具體做得好的地方，附對話或音訊時間點。
2. 呈現五項分數、依據與無法評估項目。
3. 客觀指出最值得改善的一件事，提供可實際改說的版本。
4. 顯示合規提醒與是否已修正。
5. 提供「同一情境再練一次」及下一個挑戰。

鼓勵須有證據，不能為了稱讚虛構優點。角色示範與正式學員演練紀錄分開，不混算成長分數。

## 9. 成長閉環與可比較紀錄

最小閉環為：**選一項能力 → 演練 → 找一個改善點 → 示範改法 → 立即重練 → 並排比較 → 下一挑戰。**

重練沿用情境、角色與難度，但重新初始化本場信任與已揭露狀態，避免把第一次完成的狀態當成第二次起點；使用者已知情境答案的影響須納入解讀。同情境改善不能直接宣稱可泛化至所有客戶。

紀錄至少包含：使用者所有權、session UUID、情境版本、模式、難度、重練關聯、練習目標、必要對話證據、五項評分及可用性、改善建議、合規事件、時間、實際 provider/model、promptVersion、rubricVersion、教材及規則版本。

前後比較呈現改說內容、可觀察行為及各項分數，不只顯示總分。版本或條件不同時須標示不可直接比較；不得把更換模型造成的星等變動當成進步。

產品指標包括首練完成率、首練耗時、語音中斷與評分失敗率、同情境重練率、七日回練及指定弱項改善。重練率須明確定義分母、時間窗及排除示範場次；不把先前舉例的 60% 當已核定 KPI。蒐集最少必要事件，不以原始客戶資料作分析。

## 10. Astra 評估後的產品與工程結論

| 評估發現／建議 | 本藍圖的處理 |
|---|---|
| PWA、Model Gateway、狀態機已有基礎 | 延續；不因移植目標而全面重寫 |
| 跨帳號歷史、文件、金鑰可能混用 | 第一優先修復，未通過隔離驗收不擴大使用 |
| 刪除後雲端資料可能回流 | 建立跨裝置刪除語意與離線重連測試 |
| 文件不上雲端告知不準確 | 區分裝置、Firebase、AI 服務商資料流 |
| 理賠／法規承諾超出能力 | 條款閱讀輔助、來源核對及不足時停止結論 |
| 整包同步有併發覆蓋風險 | 每個 session 獨立寫入，處理衝突及刪除 |
| 評分缺校準、模型與規則版本 | 建立專家基準、版本化與跨模型回歸 |
| 缺乏重練成長閉環 | 優先於增加功能數量 |
| 公開前端無法保密核心 IP | 作產品與部署決策；混淆程式不是保密手段 |
| 登入不等於內部門禁 | 內部發行前落實服務端資格檢查 |
| 缺 CI、mock、裝置與真實模型驗證 | 建立分層測試及發布證據 |

不採用報告「0～3 天」作交付承諾；資料遷移、刪除與權限需完整 Hardening Sprint 及回復演練。IP 保護不自動觸發全面後端重構，但真正的權限控制不能因延後重構而省略。

## 12. V1.0 定義

V1.0 是可擴大內部使用的獨立產品版本，PWA 可作為交付形式，並不以 App Store 上架或原生重寫為必要條件。

必要交付為：

- 4+1 五大能力可完成各自流程；電話約訪保留挑戰與示範模式。
- 客戶分析僅收三類資料，輸出三項待驗證需求假設。
- 三種演練均提供事前範例、可使用語音、即時自律指正與事後回饋。
- 商品教材可完整處理或誠實揭露缺口，所有商品主張可追溯。
- 問答查核遵守第 7 節，查不到不冒充已驗證。
- 有效語音演練能提供五項有證據的五星評分；資料不足時誠實降級。
- 學員可重練同情境、比較改善與取得下一個挑戰。
- 跨帳號隔離、資料遷移、刪除與內部使用權限均有驗證。
- 已完成專家評分校準、GPTs 行為對照及 10～20 人試點。
- 支援裝置、語音限制、資料處理方式與恢復操作已有可用說明。

僅有首頁、功能按鈕、文字聊天或單次評分，均不足以認定 V1.0 完成。完整聲音評分若尚未落地，應維持試點版本並明示限制。

## 13. Out of Scope

以下不列入 V1.0 必要交付：

- 第六、第七個獨立主要功能，或無邊界的通用聊天服務。
- 真實客戶 CRM、聯絡名單匯入、個資截圖辨識、病歷與保單個資管理。
- 代打電話、代傳訊息、代客投保、自動成交或執行保單交易。
- 保證核賠、精確個案理賠決策、法律或稅務結果保證。
- 全面原生 iOS／Android 重寫、必備本地模型或 Gemma 整合。
- 為隱藏提示詞而進行無驗證收益的全面後端重構。
- 完整主管儀表板、組織績效排名、自動人事考核與大型個人化課程平台。
- 收費訂閱、商店上架、商業服務承諾及完整企業教材治理平台。

真正的 Barge-in、回音消除、本地 STT 與長時間原生語音，可另作概念驗證；V1 不假稱 Web Speech 已具備這些能力。必要的聲音評分、權限與安全工程不因本節而排除。

## 14. 開發原則與驗收重點

### 14.1 開發原則

1. 程式管理狀態、權限、資料邊界及輸出驗證；模型負責在允許範圍內生成語言。
2. 保留 Model Gateway 與 Judge 分工；變更模型須回歸測試並保存實際版本。
3. 不以提示詞代替帳號隔離、來源驗證、刪除或內部門禁。
4. 不以 UI 完成度代替教練品質，不以平均星等代替學習成效證據。
5. 小步修改、先建立基線；資料遷移提供備份／回復方案，禁止不明所有權資料自動合併。
6. README、資料告知、現況文件與決策紀錄同步更新；過時決策標示被何項決策取代。
7. 允許經審核、鎖版與可維護的必要依賴，不把零相依當產品目標。
8. 預設使用繁體中文、清楚角色與低壓教學；保留字體縮放、可理解的權限與錯誤提示。

### 14.2 必要驗收案例

| ID | 測試情境 | 通過重點 |
|---|---|---|
| ACC-01 | 輸入少量客戶背景 | 三項假設各具依據、限制與接觸問題，不捏造資料 |
| ACC-02 | 輸入姓名／電話或貼個資截圖 | 系統攔截；教材入口不能繞過規則 |
| ACC-03 | 電話約訪切換兩種模式 | 角色明確、需使用者觸發；AI 示範不計入學員成績 |
| ACC-04 | 需求探索連續追問及恢復演練 | 不提前洩漏；已揭露資訊與狀態一致 |
| ACC-05 | 各演練開始前查看範例 | 可取得可用範例，且不洩漏本場隱藏答案 |
| ACC-06 | 說出已確認違規句及相似但合規句 | 前者在下一正常回應前介入並可重說恢復；後者不誤判 |
| ACC-07 | 上傳缺頁、解析不全或互相衝突的教材 | 顯示缺口／版本差異，不宣稱完整閱讀 |
| ACC-08 | 問教材未載明的商品條件 | 不補造，明確無法確認；有效主張附可定位原文 |
| ACC-09 | 問法律／稅務問題及模擬官方來源失敗 | 先查核；成功附適用來源，失敗不給確定結論 |
| ACC-10 | 有效音訊、純文字、低品質錄音分別評分 | 五項欄位固定；缺聲音證據不捏造聲學分數 |
| ACC-11 | 回饋後重練同一情境 | 先肯定再改善，可比較前後並顯示版本差異 |
| ACC-12 | A 登出後 B 登入，包含文件與金鑰 | B 無法讀取、使用或同步 A 的任何受保護資料 |
| ACC-13 | 舊資料遷移或中途失敗 | 不錯配所有權、不靜默丟失，能回復 |
| ACC-14 | 雲端刪除後重新登入及離線裝置重連 | 紀錄不復活，失敗狀態與重試可見 |
| ACC-15 | 兩台裝置同時新增不同場次 | 兩筆均保留，不整包互相覆蓋 |
| ACC-16 | 未取得試點資格者直接呼叫受保護服務 | 服務端拒絕，不能僅靠前端判斷 |
| ACC-17 | 教材／模型輸出含操控指令或惡意 HTML | 不改寫規則、不執行注入內容、不洩漏金鑰 |
| ACC-18 | 真人裝置拒絕麥克風、斷線、背景恢復 | 有恢復路徑、不重複提交、不靜默遺失演練 |

### 14.3 測試與發布證據

- 每次變更：語法與資源檢查、確定性狀態／合規／隔離／刪除測試，不強制需要 AI 金鑰。
- 合併前：mock 模型的 4+1 全流程測試、同步與錯誤恢復；涉及資料安全須追加所有權與遷移驗證。
- 發布前：真實模型整合、Golden Reference、來源取得與引用驗證、Firebase 權限及實機語音。
- 裝置矩陣至少評估 iPhone Safari PWA、iPhone Chrome、Android Chrome、iPad、Windows Chrome／Edge，記錄實際支援組合與限制，不能只以桌面成功推定手機成功。
- 每項驗收保存版本、測試條件、結果及未解缺陷；安全隔離、刪除、虛構來源與語音評分造假等必要要求不得以整體分數抵銷。
