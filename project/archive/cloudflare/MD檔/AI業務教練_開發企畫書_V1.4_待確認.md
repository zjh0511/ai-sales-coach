## 3. 新手圖解、記住 API Key 與模型選擇

### 3.1 使用者真正會看到的流程

第一次：Google／E-mail 註冊登入 → 選一家平台 → 看中文圖解申請 Key → 貼上 Key →「驗證並載入模型」→ 選模型 →「儲存並開始」。

下次：登入同一 App 帳號 → 顯示已保存的服務商、Key 遮罩及上次模型 → 直接開始，不需重新貼 Key。關閉網頁、重整或重新登入都保留設定；在其他裝置登入相同帳號也可使用已保存設定。App 登入失效仍需重新登入，不能讓未登入者使用已保存 Key。

初次選擇後按儲存才持久保存，介面明示「加密保存至你的帳號，下次不用再貼」。可取消保存而僅當次使用；一般使用路徑以記住 Key 為主。各平台只需申請一家，Google 登入 App 不會自動產生 Gemini Key。

E-mail 流程包含帳號驗證與密碼重設。未登入也能看教學，未設定有效 Key 不會自動消耗開發者額度。

### 3.2 實際截圖教學：看得到按鈕，才知道點哪裡

登入首頁設三張平台卡，各有「看圖一步一步做」及「開啟申請頁」按鈕；不把官方英文文件當作主要教學。圖片改採真實瀏覽器截圖，附紅框、編號與必要箭頭，直接指出實際按鈕；V1.2 的生成式示意圖不再用作申請操作教學。中文步驟及卡住協助繼續保留。

底圖必須是實際網站畫面，不重繪或生成按鈕、選單及表單；標示採獨立註解層。可以裁切與放大操作區域，但須保留辨認頁面的位置線索。記錄來源網址、擷取日期與登入狀態；正式上線前重新核對。網頁每一步有可選取的文字、上一頁／下一頁、進度與返回 App 提示；不要求新手理解程式碼、環境變數或 REST API。申請按鈕開新分頁，原本教學位置保留。

**先讓使用者知道：API Key 就像「讓教練使用你 AI 帳戶的通行證」。免費建立通行證，不等於全部模型免費或無限使用。三家文字 AI 的免費方案與額度，和本 App 完全免費語音政策是兩件事。**

1. 開啟以上任一入口，用自己的 Google 帳號登入；若首次使用出現條款，依畫面完成。
2. **看第一張圖：點左側選單最下方的「鑰匙圖示」**，就在紅色箭頭指的位置，進入「API Keys」（API 金鑰）頁面。

4. 接著依平台提示建立金鑰；若要求選擇「Project」（專案），選擇自己有權使用的專案，或依提供的流程建立。這個後續表單未出現在本次截圖中，暫以文字指引，不補造操作畫面。
5. 建立完成後複製完整 Key。成功／複製頁同樣尚未取得實景，正式教學驗收前補齊並完全遮蔽金鑰。
6. 回本 App 選「Google Gemini」，貼上 → 驗證並載入模型 → 選免費方案可用的文字模型 → 儲存並開始。App 此流程仍為待開發規格。
免費路徑先不要開啟「Set up billing」（設定付費帳單）。若帳號已有付費計費，不能因同一模型另有免費方案就保證這把 Key 不收費；App 需顯示帳戶計費狀態未知或需本人確認。找不到專案／受地區或帳號限制時，教學提供另一平台入口，不叫使用者輸入信用卡解鎖。

依據：[Google Key 說明](https://ai.google.dev/gemini-api/docs/api-key)、[Google 免費／付費模型資訊](https://ai.google.dev/gemini-api/docs/pricing)。入口位置依使用者提供的實際截圖確認；費用說明沿用前版官方文件依據，本次未新增申請帳號或 Key。

#### B. OpenRouter：建立 Key，再選免費模型

![OpenRouter 實際建立金鑰圖卡](D:/Hao+App/AI業務教練App/MD檔/API申請實景圖卡/OpenRouter_實景申請圖卡.png)

[開啟 OpenRouter 申請頁](https://openrouter.ai/settings/keys)

1. 先註冊登入；「Sign Up」是註冊，「Log In」是登入。
2. 開啟「API Keys」（金鑰管理），點右上角「New Key」（新增金鑰）。本輪實際畫面已確認，不再沿用舊圖的 Create Key 入口名稱。
3. 「Name」（名稱）填「AI 業務教練」即可。若有額外限額／到期設定，不確定時看本 App 對應中文提示，不把未查證的數字設定冒稱免費保證。
4. 確認表單後點右下角「Create」（建立）。建立成功後的複製畫面本輪未拍攝；不為截圖另建金鑰，之後由本人操作時補拍並完全遮蔽 Key。
5. 在 App 選「OpenRouter」→ 驗證並載入模型 → 選標示「:free」且目前確認零價格的相容模型 → 儲存並開始。

免費路徑不需先為付費模型儲值。免費模型也有限流與可用性限制，暫時用完就等候或自行選其他可用免費模型，App 不自動切付費。「Add credits」是加值；不把它列為這份免費入門教學的必要步驟。

依據：[OpenRouter 申請流程](https://openrouter.ai/docs/quickstart)、[免費模型說明](https://openrouter.ai/docs/guides/routing/model-variants/free)。

### 3.3 記住 API Key：帳號綁定、加密保存

本輪明確改為持久保存，取代 V1.1 的僅記憶體方案。建議使用受控後端的密鑰保管機制：驗證通過、使用者按「儲存並開始」後，使用伺服器端受管理的加密金鑰加密 API Key，將密文綁定 App UID 與 credentialId。資料庫只保存密文及必要資訊，解密權限限實際發出模型請求的服務。

前端輸入經 HTTPS 傳送，保存後立即清掉完整 Key 欄位；下次只取得「Google／已保存／尾碼 ****」等遮罩資訊與 credentialId，不從後端下載完整 Key。每次呼叫驗證登入及憑證所有者，在請求期間解密使用。加密金鑰與密文分開管理，記錄加密版本以便輪替；不以 Base64 或把解密鑰匙放同一資料表當加密保護。

產品設定頁說明「Key 會加密儲存在 AI 業務教練後端，僅用於你的模型請求」。服務端仍能在使用時解密，因此不宣稱零知識或端對端加密。App 登出清除前端狀態與會話，但保留該帳號加密 Key；A 登出後 B 無法看到或使用 A 的憑證。

提供「更換 Key」「移除已保存 Key」「重新載入模型」；移除時重新驗證登入，立刻停用該憑證並刪除密文及其偏好。刪除 App 帳號一併刪除全部憑證。備份若存在，須有明確保留與刪除期限，恢復時套用刪除紀錄，不讓舊憑證復活。App 移除不等同平台撤銷，設定頁另有平台管理入口。

Key 不寫入瀏覽器持久儲存、Git、網址、分析事件、錯誤日誌、追蹤系統或明文備份；公開部署產物仍排除 API Key.txt。後端採白名單服務端點、最小解密權限與帳號隔離。憑證資料不跟訓練摘要混放。

### 3.4 貼上 Key 後載入模型，記住每把 Key 的上次選擇

在 Key 輸入區下面立即呈現模型選擇區，未驗證前提示「貼上 Key 後，按驗證並載入模型」。不在每輸入一個字元時發送請求。驗證服務商及 Key 後取得模型目錄，再篩選本 App 能使用的文字對話模型，排除純圖片、音訊、向量等不相容項目。

| 平台 | 取得方式與限制 |
|---|---|
| Google Gemini | 使用 models.list 取得目錄及支援方法，配合 App 介接支援及官方價格資料；目錄不等同帳號免費額度。 |
| OpenRouter | 使用官方模型目錄及適用的使用者篩選資訊，讀取模型 ID、能力與價格；公開目錄成功不代表 Key 已驗證。 |
| Groq | 使用已驗證 Key 請求模型列表，搭配官方支援模型／方案資訊；API 列表不保證剩餘額度或零價格。 |

來源：[Gemini models](https://ai.google.dev/api/models)、[OpenRouter 模型目錄](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)、[Groq models](https://console.groq.com/docs/models)。

列表顯示易懂名稱、完整模型 ID、費用標籤（免費模型／免費方案有限額／付費／尚待確認）、相容狀態及資料更新時間。預設提供「免費入門」篩選，未能確認為免費的模型不冒貼免費標章；Gemini／Groq 的帳號計費方案若無法由 API 查得，請使用者依中文教學核對，不由模型名稱推定免費。付費模型需明確由使用者展開、看到計費提示後選取；語音仍不得走付費路徑。

選擇後先顯示「已選擇」，按「儲存並開始」保存偏好。可提供使用者主動觸發的小量測試，事先說明可能耗用其 API 額度；不能為每個模型自動跑一次生成測試。目錄、認證及實際推論成功分開記錄，不聲稱列出即可用。

偏好以 UID＋服務商＋credentialId 保存 lastSelectedModelId、最後成功模型與更新時間；重新登入或下次用同一 Key 時預設上次選擇。相同 Key 再貼上時，可用服務端具密鑰的指紋比對至同帳號原 credentialId，不以尾碼辨認，也不跨帳號去重。換新 Key 視為新憑證，重新驗證及選模型，不直接繼承舊 Key 的權限。

再次進入時先呈現上次模型並背景更新目錄。下架、無權限、變付費或不相容時保留名稱並標示原因，暫停該模型使用，請使用者重新選擇；網路失敗時保留舊設定並標示未更新，不自動改模型。免費價格資訊過期且無法查核時，不把舊的零價當成現行保證。

每次演練鎖定該場模型與版本；更換模型在新場次生效，紀錄保留實際用過的模型，避免重練分數混用。三家共用錯誤處理，不自動借用別人的 Key、開發者 Key 或切換服務商。
## 4. 免費語音方案與能力界線

### 4.1 確定限制與首選方案

語音辨識與朗讀不接付費語音 API、不用限時試用或有限免費配額冒充完全免費，也不在超限後自動改走計費服務。

首選驗證瀏覽器／作業系統提供的 Web Speech：SpeechRecognition 作辨識，speechSynthesis 作朗讀，語言設定 zh-TW。此方案不另向使用者收取語音 API 費用，也不需申請語音 Key；它是使用裝置語音能力的介面，並非已選定、各裝置一致的單一免費模型。

**目前尚未驗證一個同時滿足「完全免費、台灣語調、輕量、所有目標裝置穩定」的固定語音模型。**因此 Web Speech 是待驗證候選，不能在企畫階段宣稱已解決全部條件。官方文件顯示辨識支援度有限，部分瀏覽器使用雲端引擎；聲音清單取決於裝置。[辨識文件](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[朗讀聲音清單](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)

開發後先枚舉裝置可用音色，優先列出 zh-TW 供試聽、選擇語速；未找到時明示，不把其他地區音色冒稱台灣語調。繁體字輸出另由文字流程驗證，不能靠語音語言設定保證。

若裝置不支援免費語音，顯示原因，提供文字輸入與已驗證瀏覽器說明；文字是替代入口，不能算該裝置語音驗收通過。不自行啟用付費或配額型語音。

永久免費與未來服務政策無法替瀏覽器廠商保證；若候選失效，停止該語音路徑並重新評估。若必須採開源模型，需驗證授權、運算與下載大小，不能把主機費或大模型下載成本隱藏成「全免費」。未驗證前不加入首輪依賴。

### 4.2 語音互動

第一版採輪流說話：開始收音 → 使用者結束本句／系統判定句尾 → 轉錄與檢查 → AI 產生回應 → 朗讀。持續顯示麥克風、目前角色、停止播放及結束演練按鈕；處理拒絕權限、無聲、斷線、切背景與恢復。

不將輪流說話宣稱為 ChatGPT 式全雙工打斷。辨識可能送雲端，啟用前告知；口述個資可能在轉錄檢查前已送出，不能承諾零外傳。

### 4.3 免費限制下的五項回饋

固定呈現五項，每項可評時滿分五顆星：說話流暢度、聲音語調的親切感、客戶談話的內容掌握、用戶的自信心、用戶的專業度。

文字內容由使用者選用的文字 AI 判讀；實際聲音證據僅採免費且經驗證的裝置端分析途徑。不得為完成評分偷偷將音訊送往計費音訊模型。文字 AI 呼叫仍依使用者自己的 API 方案計算，與語音免費分開呈現。

免費錄音／聲學特徵可以提供部分時間、停頓及節奏證據，但不能直接把音高或音量換成親切感與自信星等。免費語音 API 本身也不會自動提供可信的完整五星評分；聲音評分須先做概念驗證並由講師校準。

有效證據不足時保留五欄，缺項明示「無法評估」及原因，不補星、不用轉錄冒充已聽過聲音。若免費方案無法支撐完整五項，回報缺口，首輪只能標示受限測試版；不得宣稱達成完整五星語音評分，也不自行把此限制當成使用者已放棄原需求。

回饋先肯定具體亮點，再列星等依據、客觀改善點、可直接重說的版本與合規修正狀態，最後提供同情境重練。自信評的是本次表達，不推斷人格。

## 6. 首輪兩項功能的完整流程

### 6.1 客戶潛在痛點分析

性別、年齡、背景 → 個資檢查 → 官方查核 → 三項待驗證需求假設 → 初步接觸問題與開場方向。

只提供三類客戶欄位，背景知道多少寫多少；不強迫補齊。每項分析包含已知依據、不確定性及可用提問，不能僅按性別或年齡斷定財力、家庭或購買意願。資料不足時提供三個探索方向，不虛構客戶事實。

禁止圖片選取、貼上及拖入，拒絕客戶個資截圖；文字中的識別資訊先攔截並引導改成概括背景。可將使用者選定的接觸方向帶入已開放的電話約訪，尚未開放的需求探索不提供可執行入口。

### 6.2 電話約訪語音演練

設定客戶關係、目的、非識別背景、預期反應與難度 → 提供查核後的邀約範例 → 選擇雙模式 → 開啟免費語音 → 演練與即時指正 → 回饋 → 同情境重練。

程式控制角色、背景可知範圍、回合與結束條件；模型在此範圍內生成語言。初次採新手友善情境，避免 AI 開場洩露全部答案。邀約成功不是唯一評分依據，不獎勵施壓或誤導。

回饋提供對話證據、可評的五項星等、待改善話術與再次練習按鈕；重練保留情境與難度，重設本場互動狀態。首輪可保存同帳號此裝置的必要摘要並提供刪除，跨裝置同步另期實作，不宣稱已有雲端成長紀錄。

## 7. 首輪不可省略的共同機制

### 7.1 個資與資料保護

客戶背景、自由文字與語音轉錄均先做可行的識別資料檢查；前端與後端各有驗證，不只放警語。測試使用合成人物，原始背景與逐字稿不進一般分析日誌。語音預設僅在裝置端當次處理、不做長期錄音保存；瀏覽器辨識服務自身的資料處理另行告知。

App 帳號身份與客戶背景分開處理。本機練習摘要依登入者 UID 隔離，登出清除記憶體，換帳號不得看到前人的資料或 Key。清除本機紀錄確實刪除；首輪不做紀錄雲端同步，因此不提供虛假的「跨裝置刪除已完成」。未來引入同步時再驗收刪除與離線重連。

### 7.2 回答前官方查核

保留先查 [全國法規資料庫](https://law.moj.gov.tw/) 的原要求。痛點分析、參考話術、教練指正與回饋等實質教練回答，先取得相關官方資料再作答，不默默豁免一般教學內容。純虛構客戶反應延續前版的角色回應界線；一旦含專業事實仍須查核。

查核包括取得官方正文、版本／日期、條號及支持結論的內容；顯示來源連結與查詢時間，不能只靠搜尋摘要或模型自稱查過。成功查詢而無直接適用法條時，清楚標示是教學建議；連線失敗或正文不可讀時暫停實質回答並提供重試。

自律規範視需要補充主管機關、公會與公司正式文件，不能把所有自律規範當作全國法規資料庫皆有收錄。官方取得方法與更新機制在技術驗證時確立，不要求每家文字 AI 原生具備網路搜尋。

### 7.3 即時自律指正

在學員語句辨識完成後、AI 下一次正常客戶回應前完成檢查。疑慮出現 → 暫停情境 → 查核依據 → 說明原句問題 → 提供合規替代表達 → 學員重說 → 恢復原角色。

轉錄不清或引用他人違規話術須先澄清；區分疑慮與已確認違反。規則保存來源、版本與正反例。檢查失效不得靜默繞過；合規事件獨立呈現，不以平均星等掩蓋。不能只在演練結束後提醒。
