# 把含本機模型的 App 部署到 GitHub Pages

> 2026-08-21 建立。所有數字都是實測值，不是估計。

---

## 1. 一句話的答案

**程式放 GitHub Pages，模型放 HuggingFace。** 兩者都不用付錢，而且程式裡已經是這個預設路徑
（`mirrorBase: null` 就會去 HuggingFace 抓）。

模型檔 2,076 MB 不可能放進 GitHub——單檔上限 100 MB、站台上限 1 GB，
而且 Git LFS 的檔案 Pages 不會解析（只會回傳指標檔）。

---

## 2. 實測過的可行性

| 項目 | 限制 | 我們的狀況 | 結果 |
|---|---|---|---|
| Pages 單檔上限 | 100 MB | `docs/` 最大單檔 23.6 MB（`ort-wasm-simd-threaded.asyncify.wasm`） | ✅ |
| Pages 站台上限 | 1 GB | `docs/` 共 60 MB | ✅ |
| 模型檔 | — | 2,076 MB，在 repo 根目錄的 `models/`，已 gitignore | ✅ 不會被推上去 |
| `SharedArrayBuffer` / COOP+COEP | Pages 設不了自訂標頭 | **不需要**。實測 `crossOriginIsolated === false`、`SharedArrayBuffer === undefined`，2 GB 的 4B 照樣執行 | ✅ |
| HuggingFace 跨來源提供模型 | 需要 CORS ＋ Range | 用 `Origin: https://zjh0511.github.io` 實測：`Access-Control-Allow-Origin` 有回應、`206 Partial Content`、`accept-ranges: bytes`、`content-range: bytes 0-1023/2075618592` | ✅ |
| 子路徑（`/<repo>/`） | 絕對路徑會壞 | 全部相對：`import.meta.url`、`start_url: "./"`、`app.js`、`style.css`。唯一的絕對路徑 `/models/` 只在 `?mirror=1` 區網測試時用 | ✅ |
| 流量 | Pages 每月 100 GB 軟上限 | 每位使用者從 Pages 抓約 17 MB（GGUF 路線只載入 wllama 那幾個檔）；2 GB 的模型走 HF CDN，公開模型不計費 | ✅ |

**為什麼「不需要 COOP/COEP」這一項特別重要：** 這是最常見的 Pages 部署地雷——
多執行緒 wasm 需要 `SharedArrayBuffer`，而那需要 COOP+COEP 標頭，Pages 沒辦法設。
我們用的是 wllama 的**單執行緒相容建置**（Safari 沒有 JSPI 與 memory64，本來就必須走這條），
所以剛好完全不受影響。這不是運氣好，是為了 Safari 做的選擇順便解決了部署問題。

## 3. 為了公開部署做的三件事（2026-08-21）

上架前這三件事缺任何一項，別人拿到手都會用不起來。

### ① 「自己下載」改成預設

wllama 內建的下載器在 iOS 上實測是 **1 MB/分鐘**（D039），2 GB 要跑三十四小時。
原本自己下載只有加 `?dl=self` 才啟用——那對開發者夠用，對公開部署等於不能用。

現在預設就是自己下載，要退回內建下載器才需要 `?dl=wllama`。

### ② 只發布 Qwen3 4B，不自動降階

**這一項在 2026-08-21 改過方向，原因值得記下來。**

原本的設計是「跑不動 4B 就自動降到 1B 或 0.5B，讓每個人至少能練」。
使用者在 iPad 上實測 MiniCPM5 1B 之後的回報是「**對話很不OK**」，
而量測數字支持這個判斷：1B 與 0.5B 挖到的隱藏需求都是 **0／3**（4B 是 2／3）。

一個從不透露心裡話的客戶，讓「發掘需求」這個核心練習等於不成立。
**給使用者一個看起來會動、實際練不到東西的版本，比明確告訴他「這台裝置不行」更糟**——
後者他還知道要換 iPad 或用雲端金鑰，前者他會以為這個 App 就是這樣。

所以現在只發布一級：

| 模型 | 大小 | 實測依據 |
|---|---|---|
| Qwen3 4B Q3 | 2,076 MB | iPad Pro M5、桌機可用（感知延遲 0.77 秒） |

1B 與 0.5B 的定義保留在 `tiers.js`（`shipped: false`），量測台仍可用 `?m=` 指定。
手機因此明確不支援本機模型，訊息會指向「雲端模式在手機上完全可用，六大功能都能用」。

三道防線疊起來：

1. **裝置類別 ＋ 儲存配額** —— 先挑一個合理的起點。
2. **崩潰記憶** —— 上一次把分頁弄掛的模型直接排除。
3. **使用者覆寫** —— `?m=` 指定（但已知會崩潰的仍然不給）。

**⚠ 崩潰記憶有一個必須配套的細節，第一版漏了。**
旗標的用意是偵測「分頁被系統殺掉」，但**使用者在下載中按重新整理也會留下旗標**，
下一次開機就被誤判成崩潰。實機真的發生了：使用者重整之後 4B 被列入黑名單、降階到 1B。

修法是監聽 `pagehide`——它只在「頁面正常離開」時觸發（重整、關閉、換網址），
被系統殺掉時不會觸發，這正好是我們要的區別。
另外畫面上一定要有「重試（清除上次的失敗紀錄）」，
因為誤判不該讓使用者永久失去本機模式。

**只有第 2 項是真正可靠的。** D042 已經付過代價：iPhone 14 Pro 的記憶體探測
回報「wasm 2048 MB ✅、ArrayBuffer 3072 MB ✅」，看起來完全夠，
**然後載入時分頁被系統殺掉**（Safari 顯示「重複發生問題」）。
分頁被殺掉時 JS 完全沒有機會執行，連 try/catch 都攔不到。

所以崩潰記憶反過來做：**載入前寫旗標，成功後清掉。**
下次開機若旗標還在，就代表上一次沒有活著回來——那是唯一能確定
「這台裝置跑不動這個模型」的方法。記錄的是實際發生過的事，不是推測。

### ③ 下載前必須先問

2 GB 在行動網路上是實質傷害，不能靜靜地扣掉。現在流程是兩步：
偵測裝置 → 顯示「要下載哪一個模型、多大、品質差異、為什麼選它」→ 使用者確認 → 才開始下載。
畫面也會說明「只需下載一次、之後可完全離線、建議連 Wi-Fi」。

### 儲存配額：只有「連一倍都放不下」才擋

第一版把 `navigator.storage.estimate()` 的結果當權威，而且要求兩倍空間才放行。
兩個問題：受限環境會回報 `quota: 0`（而 OPFS 完全正常），
而「寫入需要約兩倍」是觀察值不是保證值。

現在的規則：
- 查不到或回報 0 → 當成「不知道」，讓他試
- 可用空間 < 模型大小 → 擋（物理上不可能）
- 介於一倍到兩倍 → **警告但讓他試**，並說明「失敗就是空間不足，清一些再來」

理由一致：擋住一台其實跑得動的裝置，比讓他試一次失敗更糟。
失敗會得到明確的配額錯誤（那是一般錯誤，不會被記成崩潰），他還有下一步可做。

## 4. 部署步驟

`docs/` 就是要發布的目錄，`docs/.nojekyll` 已經建立（避免 Jekyll 處理 60 MB 的 vendor 目錄）。

```bash
git init
git add .
git commit -m "AI業務教練：本機模型版"
git remote add origin https://github.com/<你的帳號>/<repo 名稱>.git
git push -u origin main
```

然後在 GitHub 的 repo 設定裡開啟 Pages：

- **Settings → Pages → Source** 選 `Deploy from a branch`
- **Branch** 選 `main`，資料夾選 **`/docs`**

網址會是 `https://<你的帳號>.github.io/<repo 名稱>/`。

推上去之前確認一下模型檔真的沒被包進去：

```bash
git ls-files | grep -iE "\.gguf|\.onnx" || echo "沒有模型檔被納入版控（正確）"
```

## 5. 上架前建議先在實機確認的三件事

程式改好了，但這三件事只有真實裝置能回答：

1. **iPad**：兩步流程是否順、選到的是 Qwen3 4B、下載進度是否正常、語音是否一致。
2. **iPhone**：是否自動降到 398 MB 的模型；若載入後分頁仍被殺掉，
   重新開啟時應該看到「已記下這台裝置跑不動那個模型」並自動再降一級。
   **這是最需要驗證的一項**——手機支援目前是實驗性的。
3. **完全離線**：載入過一次後開飛航模式，確認演練仍然可用。

## 6. 其他要知道的事

- **雲端功能仍然可用。** 同一份部署同時服務兩種模式：有金鑰的人可以用全部六大功能，
  沒金鑰的人用本機模型跑前三項。商品行銷、理賠諮詢、行銷諮詢在本機模式下
  會在首頁標示為不支援（需要讀 PDF 或長文回覆）。
- **授權。** Qwen3 是 Apache-2.0；而且你並沒有在轉散布權重（檔案由 HuggingFace 提供），
  授權上沒有問題。
- **`docs/vendor/transformers/` 那 36 MB** 只有量測台 `lab.html` 的 ONNX 路線會用到。
  不載入就不佔流量，只佔 repo 空間。想精簡的話可以在公開版刪掉，
  但那會讓 `lab.html` 的 ONNX 路線失效。
- **量測台是公開的。** `lab.html`、`voicelab.html`、`memtest.html`、`nettest.html`
  會跟著一起發布。它們沒有敏感內容，但一般使用者不需要看到。
  要隱藏就從 `docs/` 移出去。

## 7. 模型從第三方 repo 抓：風險與已做的緩解

模型檔不是我們上傳的，是直接抓別人的公開 repo。這樣不必自己託管 2 GB，
但把一部分風險交到了別人手上。以下依嚴重度排列，並標明現在的狀態。

| 風險 | 嚴重度 | 狀態 |
|---|---|---|
| 上游改名或刪檔 → 所有新使用者第一次下載失敗 | 高 | **已解決**：鎖 commit SHA |
| 上游替換檔案內容（供應鏈） | 中 | **已解決**：commit 的內容不可變 |
| HuggingFace 中斷或政策改變 | 中 | 不可控。只影響新使用者 |
| CORS 政策改變 | 低 | 不可控。模型下載是 HF 的核心用途 |
| 匿名下載被限速 | 低 | 目前公開模型免費不限 |
| 授權 | 低 | 三個都是 apache-2.0、非 gated（2026-08-21 查證） |
| 公司網路封鎖 huggingface.co | 中 | 使用者端環境。改用雲端金鑰或換網路 |

### 鎖 commit 是這裡最重要的一件事

原本 URL 是 `resolve/main/<檔名>`。`main` 是會移動的分支——社群 repo
重新量化、改檔名（例如加上 `UD-` 前綴）、清掉舊量化，都是常態而不是意外。
一旦發生，**我們這邊什麼都沒改，但所有新使用者都下載失敗**。

改成 `resolve/<commit SHA>/<檔名>` 之後那個 URL 是不可變的。
順帶一提，這也讓「檔案內容被替換」在結構上不可能發生，
所以不需要在瀏覽器裡算 2 GB 檔案的 SHA256
（WebCrypto 沒有串流 API，那會要求整份放進記憶體）。

目前鎖定的版本（2026-08-21）：

| 模型 | repo | commit |
|---|---|---|
| Qwen3 4B Q3 | `unsloth/Qwen3-4B-GGUF` | `22c9fc8a…` |
| MiniCPM5 1B Q8 | `openbmb/MiniCPM5-1B-GGUF` | `3d55fac8…` |
| Qwen2.5 0.5B Q4 | `bartowski/Qwen2.5-0.5B-Instruct-GGUF` | `41ba88db…` |

三個都實測過：`206 Partial Content`、`access-control-allow-origin: *`、
檔案大小與 `models.js` 記錄的完全一致（2076／1154／398 MB）。

**要升級上游版本時**：更新 `rev`、重新量 `sizes`、重新跑一次實機驗證。
`tools/selftest.mjs` 會檢查三件事都對齊。

### 那要不要複製到自己的 HuggingFace 帳號？

**現在不需要。** 鎖 commit 之後主要風險已經解決。

真的需要的時機是：HF 上游整個 repo 被刪除，或你需要放自己微調的模型。
那時候的做法是把檔案複製到自己帳號，然後改 `models.js` 裡的 `repo` 與 `rev` 各一行。
路徑已經是通的（`tools/fetch-model.mjs` 就是在做同一件事）。

代價要知道：一次 2 GB 的上傳、免費帳號的儲存限制、
而且**你會成為散布者**，授權標示就變成你的責任（現在不是）。

### 第一次下載的時間，比想像的長

實測（公司網路，2026-08-21）：**0.7～1.3 MB/s**。換算：

| 模型 | 大小 | 這個網路要多久 |
|---|---|---|
| Qwen3 4B | 2,076 MB | 約 30～50 分鐘 |
| MiniCPM5 1B | 1,154 MB | 約 15～25 分鐘 |
| Qwen2.5 0.5B | 398 MB | 約 5～10 分鐘 |

家用網路會快很多，但**不能假設使用者的網路很快**。
所以下載進度會顯示速度與剩餘時間——只顯示「38 / 2076 MB」的話，
使用者會以為當掉了（這個專案自己就發生過）。
